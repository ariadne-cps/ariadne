# Documentation migration comparison

This experimental branch tests the shared Configuration Doxygen-to-Markdown
pipeline on the full Ariadne repository while **preserving** the existing
top-level `doc` target. The old build pins an older Configuration with
different CMake APIs; replacing it or repinning the entire dependency graph
would be a separate migration with risks outside documentation.

## Comparison

| Feature | Existing top-level `doc` | Shared Configuration target |
| --- | --- | --- |
| Inputs | `source/`, `python/`, `tutorials/`, `doc/` | `source/`, `doc/`; example and tutorial sources excluded |
| Narrative documentation | Extensive `.dox` pages and Doxygen groups | Supported if included in INPUT |
| HTML | Yes, customized by `DoxygenLayout.xml` | Yes, standard layout |
| LaTeX/PDF | Doxygen and automatic LaTeX compilation when complete toolchain exists | LaTeX generated by default; PDF under separate `doc-pdf` target |
| XML | Disabled | Enabled |
| Markdown for Hugo | Not available | Via Moxygen, with filtering of private nested types |
| MathJax | Ariadne's `doc/macros.js` | Same file enabled for Doxygen HTML |
| LaTeX packages | `amsmath`, `amsfonts`, `amssymb`, `doc/macros.sty` | Same Ariadne packages/macros for LaTeX |
| Examples and images | Ariadne tutorial and Python paths; `doc/` images | No example path; `doc/` images preserved |
| Exclusions | Several old `source/` specializations and `python/pybind11/` | Repository-local `doc/site/exclusions.cmake` |
| Doxygen capabilities | Optional Graphviz detection, cached output path options, old automatic PDF | Manual `doc-pdf`, caller-controlled output and optional LaTeX |
| API filtering | Controlled by Doxygen configuration | Doxygen plus public Markdown XML filter |

## Prototype

The separate `doc/site/CMakeLists.txt` imports the **pinned, current**
Configuration under `doc/shared-configuration`, leaving the preexisting
`submodules/configuration` and old `doc` target intact. It extends
the generated shared Doxyfile with Ariadne-specific settings for layout,
mathematical macros, examples and exclusions.

```bash
git submodule update --init --recursive
npm install --global moxygen@2.1.19
cmake -S doc/site -B build-docsite -DDOXYFILE_LATEX=OFF
cmake --build build-docsite --target doc-markdown
```

Outputs are under `build-docsite/docs/{html,xml,markdown}`. To generate
LaTeX too, omit `-DDOXYFILE_LATEX=OFF`; use `--target doc-pdf` to
compile the PDF if the LaTeX toolchain is installed. The existing project
build and `doc` target remain unchanged.

### Remaining questions / limitations

- Moxygen may not faithfully translate all Doxygen `.dox` cross references,
  project-specific LaTeX macros, `\\htmlonly`, images or original hierarchy.
  The Doxygen XML is the intermediate source of truth.
- The shared converter currently uses a shallow public-reference filter and
  hasn't been validated on Ariadne's complete documentation. Publishing in Hugo
  requires additional link/image/math normalization and page grouping.
- `doc/` contains standalone `.tex` documents that Doxygen does **not**
  turn into Doxygen pages automatically; keep them as independent PDF artifacts
  rather than treating them as Markdown.
- The old Doxyfile contains obsolete options and an invalid old `a4wide` paper
  choice for recent Doxygen versions; the shared template avoids these warnings.
- Future replacement of top-level `doc` should happen only after an end-to-end
  functional comparison including the auto-generated PDF and preserved page
  cross-references, and separately from updating legacy CMake dependencies.


## Final scope of this prototype

Only `source/` and `doc/` are Doxygen inputs. The C++/Python tutorial
directories are not indexed, and `EXAMPLE_PATH` is empty. Pages devoted to
embedded example snippets are excluded via
[`exclusions.cmake`](exclusions.cmake), alongside the older source exclusions.
Direct `\\example` directives in the main page and Computing Pi page have
been removed in the experimental branch to prevent standalone example listings.
The scientific narratives and the original example sources remain otherwise
unchanged.

No customized HTML layout is enabled. Mathematical macros are loaded from
`doc/macros.js` for Doxygen HTML/MathJax and from `doc/macros.sty`
for generated LaTeX/PDF; Hugo must explicitly load equivalent MathJax
definitions when Website consumes these Markdown files. Note that the
existing definition of `\\B` differs in those two macro files, so
cross-format documents should not rely on it until reconciled.

Usage example in a `.dox` file:

```text
\\f[ x \\in \\interval{0,1} \\subseteq \\R \\f]
```

Here `\\interval` and `\\R` are defined by the Ariadne math macros.
